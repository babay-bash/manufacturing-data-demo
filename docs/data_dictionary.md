# Data dictionary

All data in this repository are **synthetic**. Facilities, products, machines, tariffs, rates,
volumes and defects are invented design targets generated by `scripts/generate_fixtures.py`
(seed `20261019`). They make no claim about any real company, plant or client.

Layers, in load order:

1. Landed sources (`data/landed/**`, committed fixture files)
2. `raw` (DuckDB schema, written by `pipeline/ingest.py`)
3. `staging` (dbt views, `dbt_project/models/staging/`)
4. `intermediate` (dbt tables, `dbt_project/models/intermediate/`)
5. `quarantine` (dbt tables, `dbt_project/models/quarantine/`)
6. `marts` (dbt tables: 6 dimensions + `fct_production_performance`, `dbt_project/models/marts/`)
7. `reporting` (dbt views, `dbt_project/models/reporting/`)

Grain notation: "one row per X" describes the model's primary key. Types are DuckDB types from
the source contracts in `pipeline/fixtures.py`.

---

## 1. Landed sources

Each contract in `pipeline/fixtures.py` (`CONTRACTS`) names a landed file, the raw table it loads
into, and its exact columns and types. `pipeline/fixtures.py::validate` checks presence, non-empty
content and exact column set (missing or extra columns fail with schema drift) before anything is
loaded. Landed files are committed, so the demo never generates or downloads data at runtime.

### 1.1 `mes/production_orders.csv` (source system MES, raw `mes_production_orders`)

- **Purpose:** MES work-order operations, one per machine x date x shift (demo simplification).
- **Grain:** one row per `operation_id`.
- **Columns:**

| Column | Type | Notes |
|---|---|---|
| operation_id | VARCHAR | Key, e.g. `OP-OH-L1-01-20260601-D` pattern (machine + date + shift initial) |
| work_order_id | VARCHAR | Degenerate dimension; one work order spans 2-8 consecutive shifts on a machine |
| site_code | VARCHAR | Facility short code: `OH` (Dayton), `MTY` (Monterrey), `DE` (Stuttgart) |
| machine_code | VARCHAR | Canonical machine ID for OH/DE sites; legacy `MTY/LINEA1/MAQ01`-style code for Monterrey |
| product_code | VARCHAR | Product ID |
| production_date | DATE | Local production date |
| shift_code | VARCHAR | `DAY` or `NIGHT` |
| shift_start_utc | TIMESTAMPTZ | Shift window start |
| shift_end_utc | TIMESTAMPTZ | Shift window end (start + 720 min) |
| scheduled_minutes | INTEGER | Planned minutes (720) |
| units_produced | INTEGER | Units produced in the shift |
| ideal_cycle_seconds | INTEGER | Ideal cycle time for the product |
| source_updated_at | TIMESTAMPTZ | MES update time |

- **Tests applied:** contract column check at landing; staging and intermediate tests in sections 3-4.

### 1.2 `qms/quality_events.jsonl` (source system QMS, raw `qms_quality_events`)

- **Purpose:** Quality reject/defect events. A unit can carry several defect events.
- **Grain:** one row per `event_id` (a unit serial can appear on several rows).
- **Columns:** `event_id` VARCHAR, `operation_id` VARCHAR, `unit_serial` VARCHAR,
  `defect_code` VARCHAR, `disposition` VARCHAR, `event_ts` TIMESTAMPTZ,
  `source_updated_at` TIMESTAMPTZ.
- **Notes:** `defect_code` values are `WINDING_SHORT`, `BEARING_NOISE`, `TORQUE_OUT_OF_SPEC`,
  `PCB_SOLDER`, `FIRMWARE_FLASH`, `HOUSING_CRACK`, `INSULATION_FAIL`. `disposition` is always `SCRAP`
  in this fixture. Six orphan events reference an operation that does not exist in MES.
- **Tests applied:** contract check at landing; see staging tests in section 3.

### 1.3 `erp/material_costs.csv` (source system ERP, raw `erp_material_costs`)

- **Purpose:** ERP goods-issue material transactions.
- **Grain:** landed grain is one row per delivered transaction. `transaction_id` is **not** unique
  (exact replays and later corrections are present by design).
- **Columns:** `transaction_id` VARCHAR, `operation_id` VARCHAR, `work_order_id` VARCHAR,
  `material_cost` DECIMAL(14,2), `currency` VARCHAR (always `USD`), `posting_ts` TIMESTAMPTZ,
  `source_updated_at` TIMESTAMPTZ.
- **Tests applied:** contract check at landing; deduplication is tested downstream (section 4).

### 1.4 `erp/energy_tariffs.csv` (source system ERP, raw `erp_energy_tariffs`)

- **Purpose:** Facility electricity tariffs with inclusive effective date ranges.
- **Grain:** one row per facility x tariff period.
- **Columns:** `facility_id` VARCHAR, `effective_from` DATE, `effective_to` DATE (inclusive),
  `usd_per_kwh` DECIMAL(8,4).
- **Tests applied:** `effective_to >= effective_from`, `usd_per_kwh` not null and non-negative,
  no overlapping periods per facility (singular test `assert_tariff_periods_do_not_overlap`).

### 1.5 `telemetry/machine_signals.parquet` (source system TELEMETRY_HISTORIAN, raw `telemetry_machine_signals`)

- **Purpose:** Historian telemetry: one `machine_state` event and one `energy_interval_kwh` event
  per 15-minute interval per machine, in arrival order.
- **Grain:** landed grain is one row per delivery. `event_id` repeats for re-deliveries.
- **Columns:** `event_id` VARCHAR, `source_tag` VARCHAR, `event_type` VARCHAR
  (`machine_state` or `energy_interval_kwh`), `event_ts` TIMESTAMPTZ, `ingested_at` TIMESTAMPTZ,
  `value_num` DOUBLE, `value_text` VARCHAR, `unit` VARCHAR (`kWh` or `Wh`; NULL for state events),
  `quality_code` VARCHAR (`GOOD` or `BAD`), `schema_version` SMALLINT (1 or 2).
- **Notable:** `value_text` carries `RUNNING`, `IDLE` or `DOWN` for state events. From 2026-07-15 the
  Stuttgart gateway (schema v2) reports energy in `Wh`. Duplicates, late arrivals, bad-quality readings
  and an unmapped tag are all present.
- **Tests applied:** contract check at landing; `event_id` not null, `event_type`, `quality_code`,
  `source_unit`, `machine_state` accepted-value tests in staging (section 3).

### 1.6 Reference (source system MASTER_DATA)

| Source file | Raw table | Columns (type) | Grain / notes |
|---|---|---|---|

| `reference/lines.csv` | `ref_lines` | line_id VARCHAR, facility_id VARCHAR, line_name VARCHAR | One row per line: `OH-L1`, `OH-L2`, `MX-L1`, `MX-L2`, `DE-L1`, `DE-L2`. L1 = Motor Assembly, L2 = Drive & Controller Assembly |

## 2. Raw layer (`raw`)

- **Written by:** `pipeline/ingest.py`, one table per contract, rebuilt from scratch on each run.
- **Grain:** same as the landed file.
- **Lineage columns added to every raw table:**

| Column | Meaning |
|---|---|
| `_source_system` | Source system from the contract (MES, QMS, ERP, TELEMETRY_HISTORIAN, MASTER_DATA) |
| `_source_file` | Landed file path relative to `data/landed` |
| `_source_row` | `row_number() over ()` within the file; used as a tie-breaker in ERP deduplication |
| `_batch_id` | Ingestion batch identifier |
| `_loaded_at` | Ingestion timestamp (TIMESTAMPTZ) |

- **Tests applied:** none in dbt. `raw` is declared as a dbt source in
  `dbt_project/models/staging/_sources.yml` with descriptions only (no source tests).

### 6.2 Fact: `fct_production_performance`

- **Purpose:** The single production performance fact. Only additive base measures are stored.
  Ratios are computed from sums using the canonical KPIs (see `docs/kpi_definitions.md`).
- **Grain:** one row per MES operation (facility x line x machine x work-order operation x date x shift).
  `operation_id` is the grain key. Every source is pre-aggregated to operation grain before joining,
  so joins are 1:1.
- **Key columns:** operation_id, work_order_id (degenerate), date_key, facility_id, line_id, machine_id,
  product_id, shift_code, shift_start_utc, shift_end_utc.
- **Measures:**

| Column | Source | Meaning |
|---|---|---|
| units_produced | MES | Units produced |
| rejected_units | QMS | Distinct rejected unit serials (0 if none) |
| good_units | derived | `units_produced - rejected_units` |
| defect_events | QMS | Count of defect event rows |
| planned_minutes | MES | Scheduled minutes |
| operating_minutes | Telemetry | RUNNING intervals x 15 |
| idle_minutes | Telemetry | IDLE intervals x 15 |
| downtime_minutes | Telemetry | DOWN intervals x 15 |
| ideal_run_seconds | MES | ideal_cycle_seconds x units_produced |
| energy_kwh | Telemetry | Deduplicated, non-quarantined energy deltas (kWh) |
| energy_cost_usd | Telemetry + ERP tariff | energy_kwh priced at the tariff for the local date (DECIMAL(14,2)) |
| material_cost_usd | ERP | Deduplicated material cost (DECIMAL(14,2)) |
| variable_cost_usd | derived | `material_cost_usd + energy_cost_usd` |

- **Data-quality and lineage columns:** telemetry_state_intervals, bad_quality_energy_intervals,
  late_arriving_events, duplicate_deliveries_removed, material_transactions, is_quality_hold
  (`units_produced > 0 and good_units = 0`), ingestion_batch_id (from MES `_batch_id`), built_at_utc.
- **Tests applied:**
  - `operation_id` unique + not null
  - `date_key`, `facility_id`, `line_id`, `machine_id`, `product_id`, `shift_code` not null and
    relationship to the matching dimension
  - `good_units`, `rejected_units`, `energy_kwh`, `energy_cost_usd`, `material_cost_usd` non-negative
  - model test `good_units + rejected_units = units_produced`
  - model test `operating_minutes + idle_minutes + downtime_minutes <= planned_minutes`
  - model test `variable_cost_usd = material_cost_usd + energy_cost_usd`
  - **warn-severity** test `performance_not_above_100pct`: `ideal_run_seconds <= operating_minutes * 60`
    (a warning, not a build failure)
  - singular tests: `assert_fact_grain_matches_mes` (one fact row per MES operation),
    `assert_rejects_do_not_exceed_output`, `assert_energy_reconciles` (fact kWh equals accepted telemetry),
    `assert_erp_cost_reconciles` (fact material cost equals deduplicated ERP cost for known operations),
    `assert_no_energy_without_tariff`

## 8. Synthetic data story and injected anomalies

Source: `scripts/generate_fixtures.py` (developer-only; re-running with the same seed produces
byte-identical files). Expected counts below are copied from `data/landed/_manifest.json`, which the
generator writes alongside the files and the tests use as the expected values.

### 8.1 Generator knobs

| Knob | Value | Effect |
|---|---|---|
| `SEED` | 20261019 | Deterministic output |
| `START`, `DAYS` | 2026-06-01, 90 days | Production period 2026-06-01 to 2026-08-29 |
| `INTERVAL_MIN`, `SHIFT_MIN` | 15, 720 | 48 telemetry intervals per shift |
| Facilities | F-OH Dayton, F-MX Monterrey, F-DE Stuttgart | Each with lines L1 and L2 and three machine types (18 machines) |
| Shifts | DAY 06:00 local, NIGHT 18:00 local | 2 shifts per machine per day |
| Work orders | 2-8 consecutive shifts per product run on a machine | Product chosen from the line's product family |
| Planned maintenance | ~1.5% of machine-shifts skipped | Shows as missing operations (`skipped_planned_maintenance_shifts`) |
| Tariffs | see 8.3 | Per-facility effective-dated rates |
| Defect codes | 7 codes; ~15% of rejected units get a second defect code | Drives distinct vs. event counts |

### 8.2 Anomalies and expected counts

| # | Anomaly | Mechanism | Expected counts (`_manifest.json`) |
|---|---|---|---|
| 1 | **Inefficient line MX-L2** | Persistent downtime (38% chance of a 2-16 interval DOWN block per shift, vs. 12% elsewhere), IDLE rate 7% (vs. 3%), mean performance 0.78 (vs. 0.90, clamped to 0.55-0.97), +1 point scrap | Visible in OEE and downtime for MX-L2 in the marts and `kpi_by_facility` |
| 2 | **Energy-heavy machine M-OH-L1-01** | Rated kW multiplied by 1.6 (Winding cell 38 kW becomes 60.8 kW), so its energy per interval is about 1.6x its peers | Visible in `energy_kwh` and `energy_kwh_per_good_unit` for that machine |
| 3 | **Quality excursion DE-L2 / P-105, 2026-07-06 to 2026-07-26** | Scrap probability 9% instead of 1.5% for that line and product in the window | Visible in `rejected_units` and `scrap_rate` for that window |
| 4 | **Stuttgart Wh unit cutover, 2026-07-15** | From that local date, Stuttgart (schema_version 2) reports energy in `Wh` (value x 1000, one decimal). Staging divides by 1000 | Accepted telemetry is still in kWh after staging; `source_unit` accepted values cover both units |
| 5 | **Unmapped tag MTY-PLC-0299** | New Monterrey machine not yet in master data; 10 days from 2026-08-10, 96 intervals per day, both event types | `telemetry_unmapped_events`: 1920 (quarantined as `UNMAPPED_SOURCE_TAG`) |
